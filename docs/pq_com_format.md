# PLANET-Q共通通信フォーマット

- 可変長なデータをやり取りしたい
- 通信の堅牢性を高めたい
- 設計変更が容易にできるような柔軟性がほしい

上記の要望を満たすためにBluetoothなどで使われているTLV方式(Tag-Legth-Value)を参考にしてプロトコルを策定した。

## プロトコル構造

まずTLVの構造について解説する。

- タグ(Tag)       1バイト   このデータが何を表すのか事前に変数名と0-255の値を対応させておくことで表す
- 長さ(Length)    1バイト   データがn (0 < n < 256) バイトあることを表す
- データ(Value)   nバイト

Value の中の複数バイトの値（u16, i32 など）はリトルエンディアン（下位バイトが先）で並べる。
TagとLengthは1バイトなのでバイト順の影響を受けない。
なお、フレーム末尾のCRCは上位バイトが先である。

このTLV形式のデータを直接つなげて以下のようなペイロードを作る

[TLVデータ, TLVデータ, TLVデータ, ...]

このペイロードに宛先や送信元、チェックサムを追加して以下のような構造となる

[0x7E, (宛先ID), (送信元ID), (ペイロード長(バイト数で)), ペイロード, ペイロードのCRCチェックサム(1バイト目), ペイロードのCRCチェックサム(2バイト目), 0x7F]

※ 先頭の0x7Eと最後の0x7Fはデータの始まりと終わりを示すものであるから、ヘッダーとフッター(0x7E, 0x7F)がほかの場所に出てきたときはスタッフィングする

- 0x7E -> 0x7D 0x81
- 0x7F -> 0x7D 0x80
- 0x7D -> 0x7D 0x7D
